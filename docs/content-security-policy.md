# Content Security Policy source inventory

SR-603 adds `Content-Security-Policy` alongside the existing `Content-Security-Policy-Report-Only` header. Both use `report-uri /api/csp-report`. The existing collector accepts legacy CSP report envelopes with either `disposition`, bounds the body and request rate, and logs only the effective directive.

`next.config.ts` supplies the baseline on all routes, including API responses and workers. `src/proxy.ts` supplies a fresh 128-bit nonce on document requests, forwards the policy to Next.js, and prevents document caching. Next.js uses that nonce on framework and hydration scripts. Inline event-handler attributes are blocked by `script-src-attr 'none'`. Neither policy allows `unsafe-eval`.

The scheme-wide HTTPS allowances for images, media, and connections preserve existing CMS and external-art behavior. They remain broader than a closed host allowlist and do not prevent HTTPS data exfiltration through those resource types.

Only Vercel Analytics is mounted in the app. No Speed Insights component or Vercel Toolbar integration is configured in this repository. Hosting-injected preview scripts have no additional allowlist exception.

## Rendering and cache behavior

[Next.js documents that per-request nonces require dynamic rendering and are incompatible with partial prerendering](https://nextjs.org/docs/app/guides/content-security-policy). Build-time hashes cannot authorize request-dependent inline RSC scripts.

The root layout calls `connection()`. `cacheComponents` is disabled, and `partialPrefetching` and its two `instant = false` segment exports are removed. The existing `use cache`, `use cache: remote`, and `use cache: private` scopes remain enabled through `experimental.useCache`. This option works in the pinned Next.js 16.4.3 build but emits a deprecation warning.

This changes public documents from a reusable prerendered shell to rendering per request. HTML has `private, no-store` browser and CDN headers. Existing data-cache scopes, tags, asset cache headers, and image optimization remain. Latency, hosting cost, and navigation behavior need release review before this draft becomes ready.

The proxy moves from the root to `src/proxy.ts`, beside `src/app`, as required by the installed Next.js file convention. The production build previously omitted the root proxy. The HTTP checks verify that the new location actually emits nonces, rather than relying only on calls to the exported function.

## Verification commands and limits

The local checks are `bun run build`, `bun run lint`, `bun run typecheck`, `bun run format:check`, and `bun test`.

The opt-in production HTTP suite runs with `CSP_TEST_ORIGIN=http://127.0.0.1:39603 bun test src/lib/enforcing-csp.integration.test.ts` against `bun run start --hostname 127.0.0.1 --port 39603`. It checks the home page, a home query variant, ArtFight, token verification, a 404, login and admin redirects, the worker, and the report collector. It also checks each inline script's nonce, nonce uniqueness, and cache behavior.

Local smoke checks use `TUTURUUU_EXOCORPSE_CMS_DELIVERY=0` and the non-secret fixture workspace ID `csp-local-smoke`. They cover rendered route shells, not live CMS content, authenticated admin interaction, or external resource execution.

Neither `playwright` nor `@playwright/test` is installed in the repository. The headless-browser check is skipped as requested for that case. Browser CSP console violations have not been captured, so there is no claim of zero violations. Authenticated uploads, Spotify playback, live CMS media, and hosting-injected preview scripts still need browser verification before release.

The unchanged report-only policy may still report `connect-src` for data or blob fetches, `media-src` for Howler's silent data URL, and `frame-src` for signed storage previews. The enforcing policy allows these uses. The collector retains its existing per-process limits, so dual-policy reports share that budget.

## Rollback

Remove the `Content-Security-Policy` entry from `securityHeaders` in `next.config.ts` and the response `Content-Security-Policy` assignment in `src/proxy.ts`. Keep the report-only header and collector. Forwarded request CSP metadata does not enforce policy in the browser. This removes enforcement without changing any hosting settings.

A full scoped revert also restores the earlier rendering configuration and file placement. Neither rollback requires a database migration.
